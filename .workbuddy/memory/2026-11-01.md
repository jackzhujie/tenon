## M3 第 6 步 + 代码回滚：Diff 视图与 revert

### 用户问：git 哪里来的，要不要打进包里
不用系统 git —— `isomorphic-git` 1.44.8，**纯 JS**，依赖链（pako / sha.js / diff3 / ignore 等）全纯 JS。
`apps/desktop/build.mjs` 用 esbuild 把整个 server 打成单文件 `server.mjs`（12.5MB），
isomorphic-git 就在里面，**没有独立二进制、没有 .node**。所以桌面包零原生模块这条不变量靠它守住。

### 落地
- **`packages/core/src/git.ts`**
  - `showCommit(dir, sha)`：一条提交自己改了什么。取 `commit.parent[0]` 比；根提交走单树 walk 全报 added
  - `diff()` 改为 `buildDiff(entries)` 的薄壳，输出加 `files: DiffFile[]`（`lines` 带两侧行号 + `patch` + `binary`/`truncated`）
  - `lineDiff` 的缺失侧从 `''` 改成 `null`（`''.split('\n')` 是 `['']`，会给新增文件混进一行 context）
- **协议**：`DiffLine` / `DiffFile` schema；新增 `git.show` RPC、`git.diff` 输出加 `files`
- **前端**：`lib/diff.ts`（`collapseContext` 折叠 ±3 行 / `diffTotals` / `shortPath`）、
  `features/diff/DiffPanel.tsx`（**absolute 覆盖预览，iframe 不卸载**；左侧版本列表、右侧逐行着色、两步确认回滚）、
  `useWorkspace` 的 `showCommit` / `revertCommit`（带序号防连点竞态）
- **`scripts/e2e-diff.ts`（`pnpm e2e:diff`，22 项）**：git.log / git.show / git.revert 全走真 HTTP

### 踩坑
- **`git.diff(sha)` 语义不对**：它是"从 sha 到 HEAD"的累积变化，点第 3 条会把之后的改动全算进来 → 必须用 `git.show`
- **`resolveRef` 对 40 位 hex 不校验存在性**：读不到是 `readCommit` 抛（英文 "Could not find"），
  只 catch 前者会让瞎编的 sha 报 `INTERNAL` 而不是 `GIT_DIFF_FAILED`
- **Electron 沙箱**：本机 shell 沙箱下 `sandbox initialization failed: Operation not permitted`
  → network service 崩溃 → `loadURL` 直接 `ERR_FAILED (-2)`，文案里没有"沙箱"字样。e2e 加 `--no-sandbox`
- 模板建好时**已有初始 commit**，`commitAll` 对干净工作区返回 undefined（设计如此），e2e 不能假设它一定产生提交

## M3 第 7b 步：回滚的数据侧 + 撤销「零原生模块」约束（v1.2.13）

### 用户决定的规则变更
「完全没必要安装包零原生模块的限制，既然都做了安装包，可以把必要的运行环境放包里」。

**核实后是个文档错误**：三条铁律是「Electron 只做壳 / 生成应用不感知运行环境 / 实验性依赖锁版本」，
「零原生模块」从来不在其中 —— `build.mjs` 和 DESIGN 把它写成"铁律 3 在打包脚本里兜住"是**误标**。

### 7b 实现（**注意：方案和原计划不同**）
原计划「postgres 档用临时库 + 逻辑拷贝绕开 pg_dump」**没做** —— 放开限制后不需要绕，但也不该接上：
pg_dump 版本必须 ≥ 服务端版本，发布档连的是用户自己的云 PG（13~19 都可能）。改为保持现状
（有 pg_dump 就用，没有报 `DB_UNSUPPORTED`），发布档数据回滚走云厂商 PITR。

- `core/src/schema-change.ts`：快照触发判据，纯路径约定（`api/migrations/**`、`*.entity.ts`、

- `DatabaseManager.snapshot/findSnapshot/restoreSnapshot`：落 `exports/db/<sha>/db.tar.gz`。
  **库不存在返回 null**（空库快照是骗人的信号）；**存完按原状停回去**（否则每次提交泄漏 38MB）
- `core/git.ts` 新增 `planRevert()`：返回 `{targetSha, parentSha, ancestors}`，`revert()` 与 handler 共用
  同一份检查，避免"预览说能做、真做时报错"
- `server/src/revert-data.ts` 的 `pickSnapshot()`：沿祖先链找最近快照，算 `skippedCommits`
- `handlers.ts` 的 `git.revert`：**顺序 = 检查 → 还原数据 → 回滚代码**（覆盖库不可逆、回滚代码可逆）
- `chat.ts` 的 `onSchemaCommit` 回调（agent 不认识 db-provisioner）→ server 接到 `preview.snapshotDatabase`
- 前端：`DiffPanel` 确认条单独一行（塞不进 36px 顶栏），勾选框**默认不勾**，只有 `schemaChanged` 才显示；

- **`git.revert` 返回值变了**：`{commit}` → `{commit, data:{requested,restored,fromSha,skippedCommits}}`，

## M3 第 9 步：发布 push（v1.2.14，M3 收口）

### 做了什么
「发布」= 把一个 commit 冻结成版本：annotated tag（说明进正文）→ 镜像到本地裸库
`~/.tenon/backups/<appId>.git` → 写 release 记录。UI 给出版本号、备份库路径与 `git clone` 命令（可复制）。

- `core/src/release.ts`：`nextVersion()` 纯函数（`v<yyyy.MM.dd>-<n>`，本地日期，同日递增）。
  **版本号同时参考发布记录与仓库 tag** —— 只信一边都会撞号
- `core/src/git.ts`：`createReleaseTag`（`git.writeTag`）/ `deleteTag` / `mirrorTo` / `uncommittedChanges` / `listTags`
- `server/src/release.ts`：闸门（`APP_BUSY` / `RELEASE_NO_COMMITS` / `GIT_DIRTY_WORKTREE`）→ tag → 镜像 → 记账；
  **镜像失败先删 tag**，否则下次发布会跳到 -2
- RPC：`release.list` / `release.publish`；错误码 `RELEASE_NO_COMMITS` / `RELEASE_FAILED`
- 前端：`features/release/ReleaseDialog.tsx` + Header 的「发布」+ `useWorkspace.publish`（失败原因就地显示，不走全局错误条）

### 关键决定
**本地这一档不用 `git.push`**：isomorphic-git 1.44 的 push 只走 HTTP 传输（本地路径也报
`requires a "http" parameter`），而"用户机器上有 Git 服务"是不该有的假设。改用对象模型搬运：
收集可达对象 → `writeObject` 写进目标裸库 → 写 ref。传的东西和真 push 一样是对象 + ref。
**真远端（GitHub 等）没接**：要凭据 + 真网络，本机验不了，写进 DESIGN §13.3 的缺口表。

### 踩坑（都已进 STATUS §5）
- **`git.writeObject` 传 string 会写坏对象**：tag 对象解压后是乱码，`fsck` 报 `object could not be parsed`，
  且不报错。内容一律 `Buffer.from(str,'utf8')`。**改用 `git.writeTag` 更稳**（它自己拼对象）
- **裸库 API 必须传 `gitdir`**：`{dir: '/x/bare.git'}` 会去找 `bare.git/.git/...` → 静默什么都不写
- **备份库不能放仓库里**：会被 commitAll 提交，镜像时自己搬自己（实测一次写 16 个对象）
- **`app.create` 自带初始提交**（`chore: 初始化应用`），"没有提交"的场景要先删 `.git` 再造
- **★ `.gitignore` 的 `release/` 让 Tailwind 扫不到 `features/release/`**：Tailwind v4 跳过 gitignore 命中的路径
  → 新写的类名（`max-w-lg` / `min-h-[76px]` / `bg-ok/5`）不生成 CSS，只有这一处样式失效。
  已改成精确路径 `/apps/desktop/release/`。判断办法：`grep 类名 apps/web/dist/assets/*.css`
- **`field-sizing: content`（Composer 用的全局 textarea 规则）会让 `rows={3}` 失效** → 对话框要写 `min-h-[76px]`

## M4 第 1 步：子 Agent 能派活了（v1.2.15）

### 做了什么
主 Agent（Builder）可以把只读的活派给子角色，拿回一段结论。**子角色是真的另一个会话**：
独立 transcript、独立工具白名单、独立提示词、同一个 `repo/`。`explore`（定位代码）与
`librarian`（查仓库内文档与依赖类型定义）现在可用；`codeact` / `e2e` / `reviewer` 的角色定义与提示词
已就位，工具没接（`readiness: 'planned'`），派活会明确回「还没接、缺什么」。

- `agent/src/roles.ts`：**唯一事实来源**（1 主 + 5 子的工具白名单 / 档位 / 提示词 / 可用状态）。
  档位（fast/comprehensive/thinking）目前只是声明 —— 设置里只能配一个 provider，按档换模型是后续步骤
- `agent/src/tools/subagent.ts`：`api.commit` 查已有子会话（`ownerTaskId` → 幂等）→
  `harness.createConversation({ ownership, agent })` → `submit`（`requestId: subagent:<role>`）→
  从子会话 transcript 取最后一条 assistant 文本当结论
- `agent/src/tools/search.ts`：`ls` / `glob` / `grep`（纯 `node:fs` + 进程内正则，有上限）
- `agent/src/models.ts`：faux **按角色分道**（`ScriptStep.as`），路由器把自己塞回队尾
- `harness-pool.ts`：装两个扩展（coding + subagent），用闭包把 harness 懒注入给工具
- `agent/src/context.ts`：导出 `agentContext`，上层（server / 测试）不必 import pi

### 关键决定
**不用 `pi-coding-agent` 的 `grep` / `find`**：它们走 `ensureTool()`，首次调用会从 GitHub 下载
`rg` / `fd` 二进制到 `~/.pi/bin` 再 spawn。本地优先产品不能这么干（没网即失败、桌面版偷偷落可执行文件、
它还自己解析 cwd 之外的路径）。自己实现 ~200 行，生成应用只有几十个文本文件，用不着 ripgrep。
**`subagent` 的子会话里没有 `subagent`**：白名单 + `toolsForRole` 双层剔除，递归派活不从提示词求自觉。

### 踩坑（都已进 STATUS §5）
- **`api.conversation(id)` 的句柄没有 `configure()`**（只有 submit/abort/waitForIdle）→
  「先建子会话再配模型/工具/指令」会拿到一个什么都没配的会话且不报错。必须
  `harness.createConversation({ ownership, agent })`，所以工具要拿 Harness（闭包懒注入）
- **`ConversationRecord` 的字段叫 `owner`**（`{conversationId, taskId}`），不是 `ownership`
- **faux 的响应工厂只服务一次**（`stream()` 里 `pendingResponses.shift()`）→ 必须
  `appendResponses([router])` 把自己塞回队尾，否则第二次请求报 `No more faux responses queued`
- **父子会话必须分道**：子 Agent 是另一次 submit，跟父会话抢同一条队列 → 父轮收尾的台词被子会话吃掉，
  表现是「派了活但没干活」
- **`[a-z]+` 认不出 `e2e`**（角色 id 带数字）→ 用它那条道永远认不出来，台词串到 builder

### 验证
`typecheck` 15 project；`test` **302 项 / 34 文件**（+25：角色表/检索 13、守卫 5、集成 7）。
集成测试断言：真建出两个会话、子会话 `agent.tools` 只有四个只读工具、两次派活两个 conversationId、
`builder` 在 schema 层被拒、planned 角色回「还没接」、**只读派活不产生空提交**、子 Agent 不改工作区。

## M4 第 2 步：任务图面板（v1.2.16）

### 做了什么
预览下方多了一条「任务」：Agent 一开始跑它就出现，展开是任务树
（主对话 / 派活 Explore / Explore 等模型，层级用 14px 缩进），空闲时整个组件不渲染。

- `packages/core/src/taskgraph.ts`（纯函数，9 项单测）：`normalizeTaskGraph` 做四件事 ——
  kind 去 `pi.` 前缀、**会话派生回挂父节点**、角色继承、按树序压平；
  `tasksNeedingRole` 挑出"该去查角色"的工具 task
- `packages/agent/src/taskgraph.ts`：每应用一个 `watchTaskGraph`（不轮询），归一化后推全量；
  角色从 tool task 的 `checkpoint.arguments` 读一次并缓存（含"查过但没有"）
- protocol：`TaskGraph`/`TaskGraphNode` 领域类型 + `taskgraph.get` RPC + `taskgraph.update` 事件
- server：handler 里 `chat.submit` 前 `ensure(appId)`；`app.delete` 先 release 任务图再关 harness
- web：`useWorkspace` 加 `graph` 状态与归约（比对 appId 防串台）+ `features/tasks/TaskGraphPanel.tsx`

### 关键发现（都是实测定下来的）
- **pi 的 `owner` 是任务树，不是会话树**：子会话里的 generation task `owner` 是空的。
  "谁派了谁"在 `conversations` 字段 —— 工具 task 派活时那里出现子会话 id，用它回挂。
- **角色不在图里**：只能在 `getTask(id).state.checkpoint.arguments.role` 里，
  且**只有 `phase: 'execute'` 之后才写进去**。判据用「工具 task 且 `conversations` 非空」。
- **`watchTaskGraph` 必须早于 `chat.submit` 挂上**：一次派活 17 帧（实测），
  等界面来问的时候前半段已经过去了。
- **静止即空**：最后一帧 `nodes: []`。所以面板"图空即不渲染"且**不攒历史** ——
  攒出来的是"看起来像最近活动"的假象。要回顾派活看 `ConversationRecord.owner`。

### 踩坑
- **`npx electron` 在本机直接 SIGTERM 137 且无输出**：`node_modules/.bin/electron` 是断掉的 symlink，
  npx 找不到可执行文件，表现成"被杀"而不是"没装"。真二进制在
  `node_modules/.pnpm/electron@39.8.10/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron`，
  加 `--no-sandbox`。
- 截图要抓"正在跑"的状态：`setTimeout` 猜时间会撞上轮次已结束（节点被回收、面板消失）。
  改成**轮询 `taskgraph.get` 到出现 delegated 节点再 `capturePage`**，一次命中。
