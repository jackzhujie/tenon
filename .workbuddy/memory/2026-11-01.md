## M3 第 1~2 步：编译期源码定位注入 + 反查解析器

### 决策
- **日志不用 CDP**（用户问的）。理由写进 DESIGN §11.1.1：CDP 只覆盖浏览器侧、要独占 target
  （用户按 F12 就被抢走，attach 直接抛）、attach 之前的首屏崩溃与 HMR 重刷窗口内的异常全丢、
  Node 侧要开 `--inspect` 等于给本机开一个能执行任意代码的端口；而应用自报在桌面 / Web / 用户自己的
  Safari / 导出成 Docker 后是同一份代码。CDP 唯一更强的是 console 全量与网络瀑布 ——
  那是未来"性能面板"的事，届时在桌面形态用 `webContents.debugger` 做**可选增强**，不进主链路。
- **Docker 产物按用户决定跳过**（DESIGN §17 / STATUS §4.2 第 8 步标 ⏸，记为欠账）。

### 落地
- **`packages/runtime-sdk/src/vite/tenon-loc.ts`**：Babel 插件。原生标签 → `data-tenon-loc`，
  组合组件（首字母大写 / 成员表达式）→ `data-tenon-callsite`；组件库目录（`src/components/ui/`）内
  不标 callsite；`Fragment/Suspense/StrictMode/Provider/Consumer` 跳过；已有同名属性不重复注入。
  决策逻辑抽成 `decideInjection()`，Babel 接线只是薄壳。
  **零依赖**：AST 形状本地声明 + 运行时校验，不 import `@babel/core`（模板没装它，
  一 import 应用自己的 `tsc --noEmit` 就红）。
- **`packages/runtime-sdk/src/browser/tenon-loc.ts`**：`resolveTarget(element)` →
  `{primary, secondary?, tag, hops}`，callsite 优先 / 命中组件库标 `component-impl` / 自身没有则向上找。
  只用 `getAttribute`/`parentElement`/`tagName`，测试不需要 jsdom。
- 两模板：`src/tenon-loc-plugin.ts` + `src/tenon-loc.ts`（sync-templates 拷 9 个文件），
  `vite.config.ts` 改成 `defineConfig(({ command }) => ...)`，只 `serve` 时
  `react({ babel: { plugins: [[tenonLoc, { appRoot: import.meta.dirname }]] } })`。

### 踩坑
- Babel 行号 1 起、**列号 0 起** → 注入值 `column + 1`（有专门测试盯）
- 注入失效是**静默**的（页面照常打开）→ `e2e:preview` 抓 `/src/App.tsx` 的真实转译产物做硬断言，
  用正则校验 `data-tenon-loc": "src/App.tsx:行:列`
- 模板 babel `plugins` 传函数元组要过 `as unknown as never[]`（`PluginItem` 类型来自没装的 `@babel/core`）
- Vite 的模块 id 可能带 `?v=xxx` → 相对路径计算前先切掉查询串
- 顺手修了 nest-api `template.json` 里 M2 遗留的过时说法（"后端用 ts-node 跑"）

### 验证
`pnpm typecheck` 15 project；`pnpm test` **187 项 / 22 文件**（+24：插件 15、反查 9）；`e2e:preview` **16 项**全过
（新增两条：定位属性存在 + 路径不含 node_modules/绝对前缀）。

## M3 第 3~5 步：inspector 交互 + 跨源回传 + 真机 e2e

### 落地
- **`packages/runtime-sdk/src/browser/tenon-inspector.ts`**（源码分发进模板 → `src/tenon-inspector.ts`）
  - 按住 Alt 进检查模式（body cursor → crosshair），`event.target` 命中元素，overlay 描边 + 跟随标签
  - Alt+Click 选中 / Alt+Drag 框选（只留**最内层**元素，上限 50，先过滤再截断）/ ESC 退出
  - overlay 三层 div 全 `pointer-events:none`；选中在 **capture 阶段** `preventDefault+stopPropagation`
  - `postMessage({source,token,context}, '*')`；用 WeakSet 做安装幂等
- **`apps/web/src/lib/selection.ts`**：父窗口侧纯函数校验（origin + source + token 三道），
  `loc.file` 当不可信输入（拒绝对路径 / `..` / 盘符 / 反斜杠）；外加 `selectionLabel()` 给 chip 用
- **`apps/web/src/hooks/useInspectorSelection.ts`**：预览地址变化就换 token；token 拼进 iframe hash
- **`packages/protocol/src/selection-text.ts`**（零依赖，进 `./browser` 子路径）：
  `composeWithSelection` / `stripSelectionBlock` —— 上下文压成首行 `[TENON-SELECTION] {json}` 送模型，
  渲染气泡时剥回原文；往返恒等有测试
- `chat.submit` 带 `selection` → `ChatService.submit` 用 `composeWithSelection` 拼进 input；
  Composer 顶部显示可删除的 chip；`SelectionContext` 协议按 DESIGN §10.2 补全（styles/elements/viewport/impl）
- **`scripts/e2e-inspector.ts`（`pnpm e2e:inspector`，12 项）**：Electron 开真 Chromium，
  父页面来自本地 http 服务（与网关**跨源**），iframe 指向网关；`executeJavaScript` 进子 frame 模拟
  Alt+Click；把收到的消息**喂给平台自己的校验函数**过一遍；另发一条错 token 的消息证校验不是空转

### 踩坑
- **假失败**：inspector 是 `main.tsx` 里 `void import()` 动态装的，比首屏晚几十毫秒；
  e2e 一点就跑 → "收不到消息"，白查了半天。改成先轮询 overlay 节点数（`installed(frame)`）再点
- `postMessage` 的 targetOrigin 只能 `*`（子页面不知道父源）→ 校验必须全在父窗口侧
- token 走 hash 不走 query（query 进访问日志）
- Vite 能解析 TS 里的 `./x.js` → `./x.ts`（源码分发的文件互相 import 时不用担心）
- 框选上限先 `slice` 后过滤 = 垃圾能挤掉真元素（测试抓到的）
