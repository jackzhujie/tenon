## M2 第 2 步完成：可观测（日志/错误面板）

### 新增
- **`packages/gateway/src/logs.ts`**：`LogStore`（按 appId 隔离、1s 内同句合并 `repeat++` 且 id 不变、
  上限截断）、`stripAnsi`、`classifyLine`（stderr / error / warn / fail → 级别）、`parseClientLog`（页面上报的 zod 校验）
- **`proxy.ts`**：`POST /__tenon/log` 在路由分发之前拦下交给 `onClientLog`，回 204，不转发上游
- **`spawnLogged` 加 `onLine` 钩子**：vite / api（含 tsc 编译报错）每行都进 LogStore
- **协议**：`LogEntry/LogSource/LogLevel`、`app.log` SSE 事件、`logs.list` / `logs.clear` RPC
- **前端**：`useWorkspace` 的 logs 状态（按 id upsert、上限 300、切应用清空、logs.list 首拉）+
  `features/logs/LogPanel.tsx`（折叠底栏、来源筛选、错误高亮、详情展开、清空），挂在 PreviewPanel 下
- **两个模板**：`src/tenon-log.ts`（onerror / unhandledrejection → 同源 POST，keepalive，零依赖）+
  `src/tenon-boundary.tsx`（ErrorBoundary，报完再渲染降级 UI），main.tsx 换成 Boundary 包 App

### 设计要点
- 日志跟应用走不跟预览跑：停预览缓冲还在，`app.delete` 才 `forget()`
- 合并后的条目照样推（id 不变 → 前端 upsert → 一条 ×N，不跳行）
- 页面上报不带任何凭证（同源相对路径就够，铁律 2 方向）

## M2 第 3 步（同日）：运行时 SDK + 跨档迁移；Docker 产物阻塞

### 环境探测（决定打法的一次实测）
`which pg_dump pg_restore docker psql` → **全部 not found**；podman/colima/orbstack 也没有。
→ 两处方案调整：
1. **跨档迁移弃用 `pg_dump`/`pg_restore` 管道**，改**纯 JS 逻辑拷贝**（用户机器上同样没有这些二进制，
   一个"零安装"的产品要求先 brew install postgresql 才能发布 = 把最难的一步留到最后）
2. **Docker compose 产物不做** —— 无法"构建并跑起来"，DoD ④ 不能靠猜收口。不产出未验证的 Dockerfile。

### 新增
- **`packages/runtime-sdk`**（`@tenon/runtime`，**源码分发**）：
  - `src/browser/tenon-log.ts`（收编自模板，onerror/unhandledrejection → 同源 POST）
  - `src/browser/tenon-boundary.tsx`（ErrorBoundary，降级 UI 改 **inline style** —— 不依赖模板 css 类名，
    这样两个模板才能字节级共用同一份）
  - `src/nest/tenon-logger.ts`（全局 `@Catch()`：5xx 一行摘要 + 堆栈、4xx 一行 warn、**必须补回响应**）
  - `scripts/sync-templates.mjs`（写入 / `--check`）+ `test/sync.test.ts`（逐字节漂移闸门）
- **`packages/db-provisioner/src/migrate.ts`**：`migrateDatabase()` —— information_schema 取表列、
  pg_constraint 取外键做拓扑排序（有环直接抛）、分批 insert（on conflict do nothing）、
  排除生成列、identity always 加 overriding、`setval` 对齐序列、逐表 `count(*)` 校验
- `DatabaseManager.migrate(appId, { mode, connectionString })`：源用当前库，目标临时起（迁完关）
- 协议新增 `DB_MIGRATE_FAILED`(500)
- **`LogStore.addLine`**：堆栈续行（`    at …`）并进上一条 detail（id 不变），不再碎成三十条
