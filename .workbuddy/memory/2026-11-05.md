## Docker 拉不下镜像的真因：虚拟机里根本没有 DNS（顺带修好 postgres 18 的卷）

用户在自己终端跑 `docker pull postgres:18-alpine` 报
`proxyconnect tcp: dial tcp 192.168.5.2:61367: connect: connection refused`。
那个 61367 是 WorkBuddy 会话代理（每会话换端口），colima 启动时从宿主环境读进
`/etc/docker/daemon.json` 的 `proxies`，代理一停就全挂。

深挖后发现两个**更根本**的环境坑：

1. **虚拟机没有 DNS**。`/etc/resolv.conf` 是 `-> ../run/systemd/resolve/stub-resolv.conf`
   的**悬空**符号链接，而 systemd-resolved 在这个镜像里 `not-found`。之前 pull 能成功
   完全是因为走 HTTP 代理（域名由代理解析）——这个坏点被代理藏了很久。
   想手动写还失败：`cannot create /etc/resolv.conf: Directory nonexistent`（先 rm 链接）。
2. **colima 每次 start 重写 `/etc/docker/daemon.json`**，手工加的 `registry-mirrors`
   活不过一次重启（exec-opts/features 保留、自定义键不保留）。

做法：把两件都挂到 `docker.service` 的 `ExecStartPre`（`/usr/local/bin/tenon-vm-fix.sh`
+ `docker.service.d/10-tenon-vm-fix.conf`，都在虚拟机里）。实测 stop → start 后
DNS、镜像加速、本地镜像全在。`postgres:18-alpine` 从"16 分钟拉不动"→ **51 秒**。

拉下镜像后补跑全栈 e2e，立刻抓到生成的 compose 有个真 bug：
**postgres 18 的卷必须挂 `/var/lib/postgresql`**（PGDATA 挪到 `/var/lib/postgresql/18/docker`），
挂 `.../data` 会让 db `unhealthy`、app 连启动都没有。改一行 + 加单测。

验证：`e2e:docker` 全栈 **21 项**全过（之前降级只跑 12 项）/ 单测 688 / typecheck 18 项目。

### 给下次的自己
- colima **不自启**，重启机器后先 `colima start`
- 用 `/usr/local/bin/docker` 绝对路径，别把 `/usr/local/bin` 塞到 PATH 前面（brew 的 Node 20 会顶掉 Node 22）
