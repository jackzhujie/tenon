## 对话可读性三件（§4.56）

用户给了两张截图 + 三条反馈：每条工具一行太吵、子 agent 面板该并进对话、markdown 没渲染。

### ① 探索合成一行 —— 第一版写错层次
在 `parts` 里合并永远只看到 1 个工具：**pi 的历史里一次工具调用 = 一条 assistant 消息**。
改成消息层聚合（`lib/message-groups.ts`）+ 只读编组（`lib/tool-groups.ts`）。
bash 只读白名单要"每一段都过"（`cat a && rm b` 必须挡住），`2>/dev/null` 不算写盘。
顺手修了"详情点了空白"（output 为空时什么都不渲染）。

### ② 子 Agent 并进对话
删掉 `TaskGraphPanel`；`lib/task-tree.ts` 按 conversationId 分组、**深度在会话内重算**；
卡片 `Explore · N 步` 缩进显示子步骤；主对话阶段落在那行"思考中…"的位置。
三个坑：不能挂在 live 上（气泡会被上一条工具结果清掉）、实时与历史重复一份、
图只在跑的时候存在（静止回收）。

### ③ Markdown：自写解析器
`lib/markdown.ts`（180 行，只产出数据结构 → React 节点，零注入面），复用 `fences.ts`。
支持标题/粗斜体/删除/行内码/围栏/列表（含缩进与勾选）/GFM 表格/引用/分隔线/链接（仅 http(s)）。
强调符要判空白边界（`2 * 3 * 4` 不是斜体）。

## alpha.2 上的两个 bug（§4.57）

### ① 工具卡片永远空（真 bug）
先误判两次：以为没存（DB 里 559 条都在）、以为 history 读 viewState 读错
（拷真实 home 跑两版实现都对）。真凶在**实时链路**：一条工具调用是两条 entry
（assistant + tool-result），`message.end` 按 entry 发 —— assistant 那条发出时结果还没到，
之后**没人回头更新**。所以"这一轮永远空、重启读历史就正常"。
修：tool-result 到达时按同一消息 id 重推 `message.end`；顺带 history 改读完整日志。
测试：SSE 断言重推后的消息带输出（关掉回填会失败，已验证）。

### ② 导出 Docker 报构建失败（假 bug）
在他仓库手跑 `pnpm run build` exit 0。真因：静态包与 docker 两个入口同时跑 build，
vite 先清 dist/ → 互相踩。修：同仓库导出互斥（`withExportLock`）+ 报错带最后 6 行输出。

### 方法论
"把用户 home 拷到 /tmp（只拷 sqlite，4MB），两版实现各跑一遍" —— 十分钟定位到哪一层，
比读代码猜快得多。
