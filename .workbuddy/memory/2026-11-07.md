### ④ 发布 lint 失败 + 导出静态包/Docker 失败（已修，§4.53）

tsc 那项绕过 shim 所以是绿的。修法：`core/node-shim.ts` 给子进程 PATH 塞个假 node。
新增 `pnpm e2e:packaged`（Electron 二进制 + PATH 无 node）验证。

## 技术栈由应用决定：加后端 + 建应用只问一句话（§4.55）

用户说「需要」，指的是「给已有应用加后端」这块地基。

### 做了什么
- `templates/api-feature/`（`kind: feature` + `hidden: true`，不出现在建应用对话框）
- `packages/generator/src/features.ts` → `applyApiFeature()`：只写新文件 + package.json **只补缺** +
  就地改 `tsconfig include` / `eslint ignores` / `docs/AGENTS.md`
- RPC `app.addBackend`（写文件 → 装依赖 → 提交一次 → 预览开着就重启）
- Agent 工具 `add_backend`（三处都接了：tools / extensions / registry —— 差点又漏）
- 建应用对话框：主字段「要做什么」，技术栈默认交给 Agent（「我要自己选」才展开模板）
- brief 存 `description`，建完塞进输入框、**不自动发送**

### 最值钱的发现
`react-vite` 的 `package.json` 有 `"type": "module"`，Nest 产物是 CJS → Node 只看最近
package.json 的 `type` → `require is not defined`。两处钉：`scripts/mark-cjs.mjs`（build:api）+ 网关
`pinOutputModule`（预览走 tsc --watch，不经过 build:api）。**从零建的全栈应用碰不到这个坑。**
