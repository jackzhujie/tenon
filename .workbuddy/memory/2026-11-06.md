## 真 PostgreSQL：跨档迁移 + 纯 JS 快照（§4.40）

用户问"接下来还有什么没做的"，盘点后选了「真 PG 迁移 + 快照」——因为这是唯一
"静默坏数据"且刚被 Docker 解锁的一档。

### 两处都不是缺测试，是设计站不住
1. **发布档快照依赖 `pg_dump`**：理由是"用户本来就有 PG 环境"，但用户有 PG **服务器**
   ≠ 本机有 `pg_dump` **客户端**。快照只在回滚那一刻用，那时报 DB_UNSUPPORTED 等于不存在。
   → `rows-snapshot.ts`：纯 JS 自描述 gzip JSON，还原在一个事务里（外键逆序 delete →
   正序 insert → setval）。不用 `TRUNCATE CASCADE`（会清掉不在快照里的引用表）。
2. **迁移的校验是「源 == 目标」**：目标库有迁移后新写的数据时（或只是重跑），
   会把正确迁移判成失败，并提示"先清空目标表再迁"= 建议删数据。
   → 改成「目标(后) == 目标(前) + 实写」，跳过的行数进 `skipped` / `totalSkipped`。

### 单测抓到的真 bug
快照还原按"行数组前 N 个值"取值。`drop column` 之后保留列不再是前 N 个 → 整行错位；
类型相容就**静默写错列**，类型不容才报 `malformed array literal: "12.50"`
（score 被写进 labels）。改成按列名取下标。

### 结构
- 新增 `introspect.ts`（表/列/FK/行数，迁移与快照共用）、`rows-snapshot.ts`、`client.ts`
  （脚本不能直接 `import 'pg'`：pnpm 严格布局下根目录看不到子包依赖）
- `scripts/e2e-postgres.ts`：起真 `postgres:18-alpine`（用 postgres 镜像的 18 卷布局坑已在昨天修过）

### 验证
`e2e:postgres` **31 项**（真容器：迁移语义 + 续号 + 重跑 + 缺表报错 + 快照往返）；
单测 +7；全量 **695** / typecheck 18 项目；`e2e:docker` 21 项仍全过。

### 还没覆盖
快照对百万行级库会把整库读进内存（无流式/分片）；`bytea` base64 会大 33%。
生成应用量级（几十表 / 几万行）没问题，换到数据导入场景要重做。

## 跨应用用量汇总（§4.41）

用户点了「下一步做跨应用用量汇总」。原来面板一次只看一个应用，5 个应用各花 $5 就看不见总额。

### 关键发现（先做探针再动手）
`Harness.open` 只读账本不需要扩展、不需要 resume，但**必须给一个真的 models registry**
（宿主构造时会 bind 它的 getAuth，给 `{}` 会崩）。最小 harness 读一次 `usage()` = **16ms**；
同一个 DB 文件开第二个句柄也能读（不影响正在用的会话）。

所以汇总**不走 `acquire()`**：那会建 5 个扩展（`codeact` 起 worker 线程）+ `configure` 根会话
+ `resume()`（真的会去执行别的应用被中断的任务）。而是 `HarnessPool.readUsageLedger()`：
同 storage + 共享 models + 空 registry + 不 resume，读完 `close(ctx)`（close 要传 ctx）。

### 三格不能省
`known`（还没账本 ≠ 花了 0）/ `failed`（读不到的应用**不加进合计**并点名）/ `priced`
（没配价格时 $0 是"没算"）。少一格这个数就骗人。

### 顺手改的口径
`formatTokens` 原来 ≥10k 取整，截图里出现 `6.3k + 4.2k = 10k`。汇总的意义就是加起来看，
改成 10k~99.9k 保留一位小数。改的是 protocol 的公共函数，连带 `usage-format.test.ts` 一起改。

### 验证
`usage-total.test.ts` 5 项（真 server + faux 真对话）：合计逐项相等 / 重启后不先打开应用也能
汇总（这条才走到"只读账本"，调过 usage.get 就被缓存了）/ known:false 不计入 / chmod 000 造
读失败 → 进 failed 且不加进合计 / 删应用后从汇总消失。`pnpm shot:usage` 真 Chromium 截图。
全量 **700** 项 / typecheck 18 项目。

### 还没做
全局**上限**（看得见 ≠ 拦得住）。账本是累计值没有时间维度，"按月"要另存快照 —— 先不做。

## 接上 GitHub 远端

仓库：`git@github.com:jackzhujie/tenon.git`（**PUBLIC**）。本地 `main` 已推到 `0d39670`。

### 两个 GitHub 身份（最容易踩的一格）
本机三把钥匙对应不同账号：

| 钥匙 | 认证成 | 对 jackzhujie/tenon |
|---|---|---|
| `~/.ssh/id_ed25519` | **jackzhujie**（仓库主） | 可 push |
| `~/.ssh/id_rsa` | jackjie1025 | **只读**（permissions.push=false） |
| `~/.ssh/id_rsa_gitee` | — | 给 Gitee 的 |

`ssh` 默认先试 `id_rsa`，所以直接 `git push` 会被拒（报的却是 403/denied，看着像没权限）。
本仓库已写 `core.sshCommand = ssh -i ~/.ssh/id_ed25519 -o IdentitiesOnly=yes`（仓库级，
不影响别的仓库）。`gh` 的活跃账号仍是 jackjie1025 → 以后 `gh pr create` 之类要先
`gh auth switch -u jackzhujie`。

### 远端整合
远端只有一个 `Initial commit`（MIT LICENSE，Copyright 2026 jackzhujie），与本地历史无关。
用 **merge --allow-unrelated-histories** 而不是 rebase：rebase 会重写 85 个提交的 sha，
而 STATUS / memory 里写着真实 sha（如 §4.40 的 `a08a4c5`），引用会立刻失效。

### 推送前的泄露检查（结论：干净）
工作树与 85 个提交里都没有 `sk-` / `ghp_` / `github_pat_` / `PRIVATE KEY`；
`.npmrc` 只有 pnpm 配置；`docs/reverse/`、`*.har` 都没被跟踪。
**但 `.workbuddy/memory` 的 10 个文件是被跟踪的** —— 仓库是公开的，这些内部笔记会一起公开。
