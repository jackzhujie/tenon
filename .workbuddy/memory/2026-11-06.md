## 真 PostgreSQL：跨档迁移 + 纯 JS 快照（§4.40）

用户问"接下来还有什么没做的"，盘点后选了「真 PG 迁移 + 快照」——因为这是唯一
"静默坏数据"且刚被 Docker 解锁的一档。

### 两处都不是缺测试，是设计站不住
1. **发布档快照依赖 `pg_dump`**：理由是"用户本来就有 PG 环境"，但用户有 PG **服务器**
   ≠ 本机有 `pg_dump` **客户端**。快照只在回滚那一刻用，那时报 DB_UNSUPPORTED 等于不存在。
   → `rows-snapshot.ts`：纯 JS 自描述 gzip JSON，还原在一个事务里（外键逆序 delete →
   正序 insert → setval）。不用 `TRUNCATE CASCADE`（会清掉不在快照里的引用表）。
2. **迁移的校验是「源 == 目标」**：目标库有迁移后新写的数据时（或只是重跑），
   会把正确迁移判成失败，并提示"先清空目标表再迁"= 建议删数据。
   → 改成「目标(后) == 目标(前) + 实写」，跳过的行数进 `skipped` / `totalSkipped`。

### 单测抓到的真 bug
快照还原按"行数组前 N 个值"取值。`drop column` 之后保留列不再是前 N 个 → 整行错位；
类型相容就**静默写错列**，类型不容才报 `malformed array literal: "12.50"`
（score 被写进 labels）。改成按列名取下标。

### 结构
- 新增 `introspect.ts`（表/列/FK/行数，迁移与快照共用）、`rows-snapshot.ts`、`client.ts`
  （脚本不能直接 `import 'pg'`：pnpm 严格布局下根目录看不到子包依赖）
- `scripts/e2e-postgres.ts`：起真 `postgres:18-alpine`（用 postgres 镜像的 18 卷布局坑已在昨天修过）

### 验证
`e2e:postgres` **31 项**（真容器：迁移语义 + 续号 + 重跑 + 缺表报错 + 快照往返）；
单测 +7；全量 **695** / typecheck 18 项目；`e2e:docker` 21 项仍全过。

### 还没覆盖
快照对百万行级库会把整库读进内存（无流式/分片）；`bytea` base64 会大 33%。
生成应用量级（几十表 / 几万行）没问题，换到数据导入场景要重做。

## 跨应用用量汇总（§4.41）

用户点了「下一步做跨应用用量汇总」。原来面板一次只看一个应用，5 个应用各花 $5 就看不见总额。

### 关键发现（先做探针再动手）
`Harness.open` 只读账本不需要扩展、不需要 resume，但**必须给一个真的 models registry**
（宿主构造时会 bind 它的 getAuth，给 `{}` 会崩）。最小 harness 读一次 `usage()` = **16ms**；
同一个 DB 文件开第二个句柄也能读（不影响正在用的会话）。

所以汇总**不走 `acquire()`**：那会建 5 个扩展（`codeact` 起 worker 线程）+ `configure` 根会话
+ `resume()`（真的会去执行别的应用被中断的任务）。而是 `HarnessPool.readUsageLedger()`：
同 storage + 共享 models + 空 registry + 不 resume，读完 `close(ctx)`（close 要传 ctx）。

### 三格不能省
`known`（还没账本 ≠ 花了 0）/ `failed`（读不到的应用**不加进合计**并点名）/ `priced`
（没配价格时 $0 是"没算"）。少一格这个数就骗人。

### 顺手改的口径
`formatTokens` 原来 ≥10k 取整，截图里出现 `6.3k + 4.2k = 10k`。汇总的意义就是加起来看，
改成 10k~99.9k 保留一位小数。改的是 protocol 的公共函数，连带 `usage-format.test.ts` 一起改。

### 验证
`usage-total.test.ts` 5 项（真 server + faux 真对话）：合计逐项相等 / 重启后不先打开应用也能
汇总（这条才走到"只读账本"，调过 usage.get 就被缓存了）/ known:false 不计入 / chmod 000 造
读失败 → 进 failed 且不加进合计 / 删应用后从汇总消失。`pnpm shot:usage` 真 Chromium 截图。
全量 **700** 项 / typecheck 18 项目。

### 还没做
全局**上限**（看得见 ≠ 拦得住）。账本是累计值没有时间维度，"按月"要另存快照 —— 先不做。

## lint 进模板与门禁（§4.46）

用户点了"下一步"（我建议的就是这条）。DESIGN §8.6 从 M1 就写着 `tsc → eslint → vitest → build`，
但**模板里一直没有 eslint 配置**，所以门禁只有两项。

### 模板侧
`react-vite` / `nest-api` 各一份 `eslint.config.mjs` + `scripts.lint` +
`eslint@10.14.0` / `typescript-eslint@8.72.1` / `eslint-plugin-react-hooks@7.1.1`。

**规则只有三条**：no-unused-vars（`_` 豁免）、rules-of-hooks（error）、exhaustive-deps（**warn**）。
理由是"被关掉的检查等于不存在"——开 recommended 全家桶会让 Agent 写一次红一次。

先用最小项目探过版本兼容（eslint 10 已出，typescript-eslint 8.72 的 peer 接受 ^10）与
三条行为：`_` 前缀豁免、只有 warn 时 **exit 0**、有 error 时 exit 1。

### 门禁侧
`runLintScript` 第三项、与另两项并行；只认 `scripts.lint`；没有就 skip。
截断**取头部**（与 test 相反）+ 单独保留最后那行 `✖ N problems`。

### 两个真 bug（不是测试写错）
1. **杀 pnpm 不杀孙进程** → 超时后 `close` 永不来 → 门禁一直转圈。这个 bug 在 test 那半边
   存在很久，只是没有超时用例覆盖。修：`detached` + 负 pid `killTree` + **超时立刻 resolve**。
2. **`MISSING_COMMAND` 一开始含 `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`** → 那行在任何失败里都有，
   会把所有真失败误报成"没装依赖"。只看 shell 的 `command not found`。

### 顺手
`ReleaseDialog` 有第二份标签表（与 checks.ts 重复）→ 收进 protocol 的 `CHECK_LABELS`。

### 验证（模板真跑，不是"配置写对了"）
两个模板各：干净 install → lint exit 0；**插一个未用变量 → exit 1 且报出精确位置**。
第二列是关键 —— 只验 exit 0 的话，`files` 模式写错也是 0（假绿）。
release 测试的 `makeCheckable` 摘掉了 lint（它只软链 typescript，留着会让门禁正确报"没跑成"，
反而盖住要验的东西），另加一条"lint 没过也拒绝发布、不留 tag"。

全量 **712** 项 / typecheck 18 project。

### 补：CI 抓到的第三个 bug（本地绿、CI 红）

改完 ELIFECYCLE 那条误判，CI 还是红：
`expected '没过（pnpm run lint 退出码 1）' to contain '没跑成'`。

两件事叠在一起，都只在非 macOS 暴露：
1. **shell 文案不同**：macOS 的 sh 说 `sh: eslint: command not found`，
   Debian 的 dash 说 `sh: 1: eslint: not found`。
2. **pnpm 把 127 折成 1**，与"查到 3 个错误"同一个退出码。

→ 最终判据：**先看脚本第一个词在不在 `node_modules/.bin`**（与环境无关，
覆盖 `eslint .` 这种最常见形式），复合脚本才退回看输出（正则认两种文案）。
误判方向选"说没装"（用户装一下就好），反过来会让人改一段没问题的代码。

**教训**：凡是碰 shell / 退出码 / 路径分隔的判断，本地的绿不算数，只有 CI 能验。

## 组件产物体积（§4.49）

用户问"接下来还有什么没做"，选了组件产物体积。

### 描述一直是错的
清单上写"三个组件各打一份 **React**，应共享运行时"。实测 `web.js` 里 532 个模块标记
**全是 typebox**，一个 React 都没有（这三个组件是命令式 DOM，根本不用 React）。

体积构成：`chord/dist/delta/tracker.js` 68.9KB、`chord/dist/object.js` 52.8KB、
`typebox/build/type/script/parser.mjs` 35.7KB……

### 两条路被堵
1. **收窄 import 无效**：想把 `contract.ts` 的 `typebox` 改成 `typebox/type`，
   但 chord 自己 `import "typebox"`（根入口）+ 5 处 `typebox/value`，省不掉。
2. **共享运行时与 Hub 自包含冲突**：第三方从 Hub 装的包里没有 node_modules，
   共享 chunk = 缺依赖的坏包。要对 bundled 三个特殊处理 → 两条加载路径，不值。

### 做的：minify + keepNames
四档实测（同一入口）：不压 751,889 / 只压空白语法 533,643(−29%) /
**minify+keepNames 351,280(−53%)** / 全 minify 311,663(−59%)。
选 keepNames：差的 40KB 换堆栈可读性，实测堆栈里 `at appIdOf (...)` 名字还在。
不做 sourcemap（.map 会打进 Hub 包，双倍体积）。

结果 3.4MB → 1.6MB。

### 验证
六个产物**逐个 import()**：server 必须有 `activate`（三个都有）；web 是自注册模块
**导出为空是对的**（我第一版断言写成"也要 activate"——错了，靠 URL appId 自己挂载）。
25 项组件服务端测试 / e2e:component 5 / e2e:hub 32 / 全量 718 / lint 0 error。

### 方法论
**盘体积先拆构成**：`esbuild --metafile` + `bytesInOutput` 一行就答"谁占的"，
比按常识猜快得多。这条欠账躺了两个里程碑就是因为没人拆开看。

## 三平台 CI：第一轮红 32 条，抓到四个 Windows 真 bug（§4.50）

用户说"好"，选了 CI 加 OS 矩阵。

### 收敛过程
32 → 10 → 0。三平台各 4–5 分钟，并行，墙钟时间没变。

### 四个真 bug（三条是产品级）
1. **`spawn pnpm ENOENT`**：Windows 的 pnpm 是 `pnpm.cmd`，且 Node ≥18.20 要求 `.cmd`
   必须 `shell: true`。四个调用点全挂（门禁 test/lint、装依赖、导出 build/install）。
   顺手把复制四遍的 `isScript ? execPath : command` 收成 `invokePnpm()`，平台做成参数
   （8 项新单测），加 `windowsHide`。
2. **删应用永远失败**：`startsWith(`${appsDir}/`)` 硬编码斜杠。改 `relative()`。
   连带 core/budget 测试红（异常 → `core.close()` 没跑到 → sqlite 句柄 → EBUSY）。
3. **没有优雅关停**：Windows 上 SIGTERM = TerminateProcess。加 stdin EOF 通道
   （`TENON_STDIN_SHUTDOWN=1` 开起来，否则 `< /dev/null` 会启动即退出）。
4. **`build:plugins` 静默空跑**：`import.meta.url === \`file://${argv[1]}\`` 在 Windows
   永不相等 → 整块 CLI 跳过、不打印、退出码 0。改 `pathToFileURL`。

### 做法上的两点
- **先加诊断再修**：第二次剩 10 条时，现象全是"HTML 里没有脚本"这种平台无关的描述。
  把断言改成先断言文本、并把 plan/activation 的 problems 带出来，第三条才定位到 build。
- **`.gitattributes` 是配套不是风格**：`* text=auto eol=lf`。逐字节比对（runtime-sdk 漂移、
  发布快照、组件签名）在 CRLF 下必红且红得莫名其妙。CI 另加一步
  `git ls-files --eol | grep i/crlf` 断言。

### 没做到（写进 STATUS）
桌面壳在 Windows/macOS 仍没跑过（要 GUI）；没出过 Windows 安装包；e2e:* 仍不在 CI。

### 补：第五、六个 bug（收尾时才发现的两个"自己的"问题）
5. **删应用与建应用后台装依赖赛跑**：`app.create` 里 `void ensureDeps()`，进程拿 repo 当 CWD。
   `maxRetries`、4.6 秒退避都治不了（占用者是我们自己）。加 `EnsureDepsOptions.signal`、
   `preview.cancelDeps()`（abort + 等 task 结束）、删除前 await 它，Windows 用 `taskkill /T`。
6. **自己写的 supervisor 夹具偶发红**（macOS）：`write('bye')` 后立刻 `exit(0)` 丢最后一行。
   等 write 回调再 exit，本地连跑 20 次验证。

最终：三平台各 **728 项 / 78 文件**全绿，各 4–5 分钟。

## 打包与 Hub 的真相（§4.51）

用户问"Hub 上线先不迟吧，现在打包是什么问题，没有运行环境是吗"。

### 回答：运行环境全在包里
- Node 不需要（Electron 二进制 + `ELECTRON_RUN_AS_NODE`）
- pnpm 随包（`Resources/server/node_modules/pnpm`）
- PGlite 的 `pglite.wasm` 跟包
- 原生模块有审计（只列清单，不失败）

### 真正的问题：从来没人跑过 `dist`
`pack:desktop` 是 `--dir`（只解包，出 `.app`）。目标（dmg/zip/nsis/AppImage）早就配好了。
新增 `dist:desktop`。

### 第一次跑失败是网络
`Timeout awaiting 'request' for 600000ms` —— zip 那半已成功，卡在下载 23MB 的 dmgbuild bundle。
同一台机器：GitHub 资产 2KB/10.7s，npmmirror 2KB/0.43s。设
`ELECTRON_BUILDER_BINARIES_MIRROR=...npmmirror...` → **1 分 15 秒出 dmg（129MB）**。
`hdiutil verify` 过，挂载是标准 dmg（app + Applications 链接）。
`smoke:desktop:packaged` 9 项全过（真启动、有 token、退出不留孤儿）。

### 结论
- Hub 不紧急：本地 bundled 组件能用，商店未配置时明确显示"未配置"
- 发给别人只卡签名（Apple $99/年）—— 钱的问题
- Windows/Linux 安装包要对应机器 + 从未验证过
