- Node：托管版 22.22.2 满足其实际 engines 要求 `^22.19.0 || ^24.11.0 || >=26.0.0`（GitHub 文档写的 ≥22.23.4 与已发布包不一致，以包内 engines 为准）。
- MCP 注册：新建 `/Users/mac/.workbuddy/mcp.json`，server 名 `rea`，命令为托管 node 直接运行 `scripts/rea.mjs mcp`（固定版本、绕过 npx 慢启动）。

- 待办：用户需在连接器管理页对该自定义 MCP 点击「信任」才会生效；可选原生分析引擎（Hopper/Ghidra/IDA）未安装，纯 JS/网站/.NET 分析无需引擎。

## REA MCP 可用性实测（结果）
- 协议层：initialize 正常，`tools/list` 返回 **207 个工具**，6 个 prompt 工作流；`rea doctor` 显示 node/host 健康。
- 可用：`open_binary` 等纯进程内静态解析正常（/bin/ls、WorkBuddy 的 Electron 主程序均解析出 Mach-O 类型/架构/sha256）。
- 不可用（本会话环境）：所有依赖外部命令的 provider 报 `process table could not be inspected: spawn EPERM`——本机 agent 环境整体禁止 `ps`（`/bin/ps` 返回 operation not permitted），REA 的清理校验必须查进程表，故判定失败。属环境限制，非安装问题。
- `inspect_sqlite_database` 另需 Node ≥24.15（DatabaseSync.limits），当前 22.22.2 不支持。
- `list_strings` / 反编译类需 Ghidra/Hopper/IDA/JADX/Kuna 引擎，均未配置。
- 测试脚本留存：`/tmp/rea-mcp-test.mjs`、`/tmp/rea-call.mjs`、`/tmp/rea-seq.mjs`（JSON-RPC over stdio 直连）。
- 结论：安装与注册正确，MCP 通道健康；深度分析能力受本机 ps 策略 + 缺引擎限制，待 Trust 后在 app 运行时内再复测。
