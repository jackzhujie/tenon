## M4 第 4 步完成：e2e 子 Agent 自己去点页面（DoD ①）

### 新增
- **`packages/gateway/src/page.ts`**（约 640 行）：`PageBridge` —— 会话 / 命令队列 / 长轮询 /
  超时挂账（`drop()` 摘除）/ 断开感知（`poll(sessionId, signal)`）/ 导航票据；
  `PAGE_SCRIPT`（注入页面的 ES5 脚本）+ `injectPageScript()` + 四个保留路径
- **`proxy.ts`**：吃掉 `GET /__tenon/page.js`、`POST /__tenon/page/hello|reply`、`GET /__tenon/page/poll`；
  HTML 注入（只 `text/html` 且未压缩，插 `</body>` 前，重算 `content-length` 并**删 `transfer-encoding`**）
- **`preview.ts`**：每个 run 一个 `PageBridge`，`pages(appId)` 给 server 查
- **`packages/agent/src/tools/preview.ts`**：`preview_read/assert/click/type/open` 五个工具 +
  窄接口 `PageDriver`（agent 不依赖 gateway，接线在 server）
- **`roles.ts`**：`e2e` 从"没接"转 `ready`；主角色 `rootTools` **不含** `preview_*`（要验页面必须派活）
- **`scripts/e2e-e2e-agent.ts`**（`pnpm e2e:e2e`，9 项）：真 Electron 里注入 `value + 2` 的 bug →
  断言失败并报出实测值 → 主角色改成 `value + 1` → 整页重载 → **同一条断言通过**

### 关键决策
- **不新起浏览器，页面反连**：网关往 HTML 注一行脚本，页面 `fetch` 长轮询领命令。
  装 Chromium 违背本地优先；Web 模式下用户本来就开着浏览器，E2E 要验的正是**用户眼前那个页面**
- **只有 HTTP 长轮询，没有 WebSocket**：网关的 `upgrade` 原样透传给 Vite（HMR 握手带自定义 header），
  同一个 handler 里既透传又自己握手是最容易写出"偶尔连不上"的写法
- **`sessionId` 存 `sessionStorage`**：改完代码整页重载是这条链路最常见的动作，存变量会让
  "改完再断言"随机失败
- **刷新只重投幂等命令**（`read`/`assert`）：重放一次 `click` 可能点出两个东西
- **断言失败返回 `isError: false`**：那是"页面与预期不一致"，模型该回去改代码；
  标成错误会让它换选择器重试。参数不合法才在**发命令之前**拦
- **`preview_open` 单独存在**是因为 React Fast Refresh **保留 state**（改完计数不回 0）

### 踩坑
- **`content-length` 与 `transfer-encoding` 并存 → 响应永远不结束**：预览一直 `failed`，
  日志一个字都没有。两个都要删。用显式长度的桩测不出来
- **扩展只 `registry.install()` 不进会话的 `extensions` → 工具"不存在"且不报错**：
  子会话里 `preview_*` 的 `execute` 一次都不进，模型若无其事地继续讲
- **整页导航会掐断挂着的长轮询**：命令被投进死连接，只能等 12s 超时。要 `AbortSignal` + `res.on('close')`
- **页内抛异常也必须回话**：`querySelector` 拿到 `null` 再读属性会抛，不在 rejection 分支回话
  就只剩超时，真实信息（"没找到第 1 个…"）根本没送出去
- **`poll` 遇到不认识的 sessionId 要回 `'reset'` 不是 `null`**：回 `null` 页面立刻再问，空转打满 CPU
- **命令超时后还要从队列摘掉**：只删挂账的话下一轮会照样投给页面执行（超时的 click 真的会点出去）
- **e2e 第一版断言"计数回到 0"失败**：React Fast Refresh 保留 state，要 `preview_open` 干净起点
- **e2e 的"断言失败"曾是假阳性**：我写 `export default` 而模板 `main.tsx` 是具名 import，
  整页 `SyntaxError` 渲染失败。加了"页面渲染正常（不是白页）"前置检查
- **本机 bash 里 `grep "pattern" file` 常返回空**（shell 注入了 shim）→ 查文件一律用 Grep 工具

### 验证
typecheck 15 project / test **375 项 / 42 文件**（344→375：gateway page 16 + agent preview-tools 13 +
server e2e-agent 2）/ smoke 9 / **e2e:e2e 9 全绿**（真 Electron）/ build:web 292.70KB（CSS 32.38KB）/
build:desktop 出包（server.mjs 12371KB）。

### 欠账
没有"跑一条用户旅程"（只有单条命令 + 断言）；无 hover / 拖拽 / 滚动；断言无截图对比；
多标签页只有最后连上的那个被驱动；`faux` 下"发现 bug"是剧本安排（判据仍来自真 DOM）。

## M4 第 5 步完成：Reviewer 出风险清单

### 新增
- **`packages/core/src/git.ts`**：`worktreeDiff()` —— 工作区 vs HEAD 的结构化差异（`base` / `omitted` /
  逐文件 patch）。复用 `workingTreeChanges`（自算 blob oid，避开 stat 快路径），40 文件上限
- **`packages/core/src/typecheck.ts`**：`parseTscOutput`（续行并入上一条、认不出的进 `other`）+
  `formatTscReport`（`ok` 由调用方那个布尔决定 —— "跑完了 + 没诊断"才算过）
- **`packages/agent/src/tools/review.ts`**：`git_diff`（默认工作区，`commit:"HEAD"` 看上一版，
  支持 `path` 过滤）+ `typecheck`（多 tsconfig、`--pretty false`、超时 SIGKILL、上限截断）
- **`roles.ts`**：reviewer 转 `ready`，白名单 `read/ls/glob/grep/git_diff/typecheck`；提示词写死
  「先 diff 再 typecheck」+ 清单格式（最多五条、`[blocker|risk|nit] path:line — 问题 — 修法`）
- **`harness-pool.ts`**：`tenon.review` 扩展进 registry 与会话 `extensions`，**不进 rootTools**

### 关键决策
- **审的是工作区不是提交**：`commitAll` 在一轮收尾才跑，Reviewer 动手时改动还没提交
- **"没跑成" ≠ "通过"**：缺 tsconfig / 缺 typescript / 超时三种各有各的话，输出里不出现 `✓`
- **类型错误是信息**（`isError: false`）：标成错误会让模型重试工具，而它该写进清单
- **多 tsconfig**：`nest-api` 的客户端与服务端是两份配置，只跑根的就等于后端一行没查照样绿
- **`lint` 没接**：模板没有 eslint 配置，硬塞会把真风险淹掉

### 踩坑
- **`scrubEnv` 会删掉 `ELECTRON_RUN_AS_NODE`**（防止生成应用子进程"把 electron 当 node 跑"），
  但 `typecheck` 是自己的子进程：`.app` 里不补回来会**真弹出一个窗口**且 `tsc` 一行不跑
- **`pnpm --filter @tenon/core test` 什么都不做**（core 没有 `test` script），要跑
  `pnpm vitest run packages/core`。exit 0 且零输出，很容易误判成"全绿"
- 本机 `grep` 依旧返回空（shell shim）→ 一律用 Grep 工具

### 验证
typecheck 15 project / test **405 项 / 45 文件**（375→405：core typecheck 10 + core worktree 5 +
agent review 11 + server reviewer 集成 2 + roles 2）/ smoke 9。

### 欠账
`lint` 未接；清单只有文本，没有结构化事件/面板；`typecheck` 不跑测试；
评审结论还不会变成"不许提交"（发布质量门禁是 M4 第 7 步）。

## M4 第 6 步：CodeAct 的 codemode 沙箱

### 落地
- **`packages/agent/src/tools/codeact.ts`**：`CodemodeSandbox`（60s / 128MB）+ 上游
  `createCodemodeExtension({ models: false, inlineBudget: 1200 })` + 改名 `tenon.codeact` + `close()`
- **`roles.ts`**：`codeact` 转 `ready`；新增 `RoleSpec.modelTools`（只有 `codemode` 递给模型）
  与 `RoleSpec.extensions`（`tenon.codeact` 只进子会话）；`plannedRejection()` 抽成纯函数
  （表里没有 planned 角色了，机制靠单测钉住）
- **`subagent.ts`**：子会话传 `modelTools` 与 `extensions: { add }`（只加子会话还没有的）
- **`harness-pool.ts`**：装扩展 + 进 registry，`close()` 里**先关沙箱再关 harness**
- **`apps/desktop/build.mjs`**：`pi-codemode` + `quickjs-wasi` 外部化并整包拷进
  `dist/server/node_modules/`；`assertCodemodeLayout()` 按运行期规则各解析一次

### 关键决策
- **能力边界是三层不是提示词**：会话 `tools`（可用集）／工具 `callers`（谁能调）／
  `modelTools`（递给模型的子集）。不设 `modelTools` = 全给，模型就会绕过脚本一次次直读
- **没有 bash、没有 write/edit**：命令一条条在转录里可审；脚本里四十条命令的输出只有脚本自己看得到。
  写工具一进沙箱就破了"子 Agent 只读"这条对五个角色都成立的不变式（规划表里的 `bash（受限）` 因此去掉）
- **`models: false`**：上游默认给脚本 `models.classify()/generateImages()`，那是脚本自己发起、
  绕过用量熔断的计费调用
- **60s 而非上游默认 300s**：一次工具调用等五分钟等于卡死
- **不用 pi-coding-agent 那份 codemode**：durable 那份的嵌套调用走 `api.executeTool()`，
  校验/重放/输出上限全部沿用，且带确定性日志

### 踩坑（打包才现形，构建却成功）
- `require.resolve('@earendil-works/pi-codemode')` 报 `No "exports" main defined`
  （exports 只有 `types`/`source`/`import`）→ 用 `realpath` 拿 pnpm 软链目标
- `quickjs-wasi` 只拷 `quickjs.wasm` 不够：`vm.js` 会 `import { QuickJS } from "quickjs-wasi"`，`dist/` 要一起拷
- 过滤 `extensions/*.so` 时别把 `dist/extensions.js` 一起滤掉（`!src.includes('/extensions')`)
- **`tools` 是会抛异常的代理**：脚本里 `typeof tools.write` 直接抛，要 `try/catch`

### 验证
typecheck 15 project / test **409 项 / 46 文件**（405→409：server codeact 集成 3 + roles 3
− 两条已失效的 planned 用例）/ smoke 9 / e2e:e2e 9（真 Electron，回归）/ build:desktop 出包。
**并在 `dist/` 里真跑了一次沙箱**：wasm 与 worker 都解析到包内，`return 42` 拿到 42。

### 欠账
脚本能用 `// @options: {"timeout_ms": …}` 放大默认超时（上游语义，我们没夹）；没配 `ExecutionEnv`，
输出超预算无法另存全文；嵌套调用不进父会话事件流；脚本不能写文件（"批量改"仍由主角色 `edit`）。

## M4 第 7 步：发布前质量门禁（typecheck / test 不过不许发）

### 落在哪
- **`packages/agent/src/checks.ts`（新）**：`runTypecheck` / `runTestScript` / `runQualityGate` /
  `formatGateSummary` / `checkLabel`。`review.ts` 的 `tsc` 跑法搬进来，工具改调它 —— 一个"什么算通过"
  只能有一个答案，两份实现 = 两份记住 `ELECTRON_RUN_AS_NODE` 那个坑的机会
- **`packages/core/src/pnpm.ts`（新）**：`resolvePnpm` 从 gateway/deps.ts 提出来，装依赖与跑 test 共用
- **`packages/core/src/db.ts`**：迁移 2 给 `releases` 加 `gate_status` / `gate_summary`（**都可空**）
- **`packages/server/src/release.ts`**：门禁排在版本号之前 → 不过就抛 `RELEASE_CHECKS_FAILED`；
  `force` 时仍跑检查、记录标 `forced`
- **`ReleaseDialog.tsx`**：三行清单（哪项 / 为什么 / 看输出），「仍然发布」要再点一次确认

### 关键决策
- **三态不是布尔**：`pass`/`fail`/`skip`，判据是"没有任何一项 fail"。混成一个 `false` 会让
  "没配测试"和"测试挂了"同罪 —— 要么没写测试的应用永远发不了，要么红了照发，两种都会让功能被关掉
- **「没跑成」是 fail 不是 skip**：有 tsconfig 却没装 typescript 归到 skip 等于"删掉 node_modules 就能绕过"
- **force 只改「拦不拦」，不改「跑不跑」**：用户有权坚持，但没权不知道自己在放过什么
- **`gateStatus` 不能有默认值**：迁移 2 之前的老记录必须是 null，给 `'pass'` 就等于伪造历史
- **`pass` 包含"全部 skip"**：那是"没得检查"，不是"偷偷发的"，不该标 forced
- **test 只认 `scripts.test`** + 带 `CI=1`（vitest 默认 watch，会挂到超时被误报成"测试超时"）

### 踩坑
- **core.test.ts 硬编码 `schemaVersion === 1`** → 加迁移就红。改成
  `MIGRATIONS[MIGRATIONS.length-1].version`（写死数字的断言最后一定会被改成 `toBe(当前版本号)` 然后失去意义）
- **错误消息里没有检查名**：`summary` 原来自带"类型检查失败…"，于是 message 拼起来重复。
  统一成 summary **不带**名字（界面有独立列），message 用 `checkLabel(id)` 补
- 既有 6 条 release 集成用例全部被门禁拦（应用故意没装依赖）→ 传 `force: true`，
  并在文件头说清"这些用例验的是发布编排，不是门禁"
- 集成测试要造"可检查的应用"：模板 tsconfig 写着 `types: ["vite/client","node"]`，
  只软链 typescript 会报"找不到类型定义" → 写一个最小 tsconfig + src，另附 `installTypescript()`

### 验证
typecheck 15 project / test **429 项 / 48 文件**（409→429：agent checks 13 + server release 4 +
core migrations 3）/ smoke 9 / **e2e:release 36→40**（门禁拦截 + force 留痕 + 两条记录都留痕）/
build:web（295KB，新增的 Tailwind 类名逐个在 CSS 里查过）。

### 欠账
没有发布前**预检**（要 `release.check` RPC，现在点了才知道过不过）；`lint` 没进闸门；
检查结果只在发布对话框里；真远端 transport 仍未接。
