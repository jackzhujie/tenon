## 导出静态包（§4.38）：DESIGN §13.1 的第二种产物第一次真的存在

### 起因是三个问题
用户问：Docker 是否必要（一键打包脚本够不够）／多端打包能否改 GitHub Action／跨应用总闸有必要吗、
token 粒度是什么。查证后发现关键事实：**`export.*` 一个 RPC 都没有**（不只是缺 Dockerfile）。
DSIGN §13.1 的三种产物只有 git push（本地裸库）落地。

### 结论（已与用户对齐）
- Docker **不能省**（它解决"运行环境可复现"6 件事，静态包只解决 2 件），但顺序要反过来：
  **先静态包，Docker 从它派生**（Dockerfile = COPY 产物）。验证放 CI（runner 自带 Docker）
- 多端打包**应该**改 GitHub Action，但第一步是质量门禁（无账号依赖），三平台打包第二步；
  且仓库**还没有 remote**，workflow 写了要推上去才生效
- 总闸要区分**熔断（per-app，已有）vs 总闸（global，缺）**；`setting-keys.ts` 里那句
  "为什么按应用而不是全局"讲的是熔断，不是总闸。token 粒度：按应用是唯一准的一层
  （`harness.usage()`），按角色做不了（欠账⑤）

### 落地
`packages/server/src/export.ts`（390 行）+ `export.static` RPC + 发布对话框入口。
产物：dist/ dist-server/ node_modules(prod) serve.mjs start.sh .env.example README.md。
四个决定：产物不含 pglite；单端口靠生成的 serve.mjs（不改模板）；跑模板自己的 build；
默认带 prod 依赖。实现时发现"从没起过预览就导出"会缺 node_modules → 复用 `ensureDeps`。

## 装 Docker（本机）+ Docker 导出落地（§4.39）

### 装 Docker：四个环境坑
1. **Homebrew 把 Intel Mac + macOS 15 归到 Tier 3**：`docker`/`colima`/`go` 都没有 bottle。
   改用官方二进制：limactl 2.2.1（还需 `share/lima` 的模板 + guest agent，只拷 binary 会报
   `template default.yaml not found`）、colima 0.10.3、docker CLI 29.9.3、compose v5.7.0、buildx v0.38.2。
2. **`~/.docker/cli-plugins/` 里全是指向已删 Docker.app 的悬空符号链接** → `docker compose` 不认、
   curl 写不进去。删链接换真文件。
3. **`~/.docker/config.json` 里 `credsStore: desktop`** → 拉镜像报
   `docker-credential-desktop not found`。去掉该字段。
4. **首次 `colima start` 报 `cannot restart, VM not previously started`**（colima 自己的怪癖），
   stop + start 一次即可。

### 磁盘：删了不释放的怪事
删 7.9G 模拟器 + 5.3G Docker.raw + 773M 缓存后 `df` 一动不动，**重启后才回来**（3.8G），
之后又慢慢涨到 22G。Macintosh 的 APFS 是异步回收 + purgeable，`df` 当场看不出来。
排查过程里量到：数据卷 232G 用满，但逐项只定位到 92G —— 差的 140G 至今没找到（iCloud 占位 /
系统元数据 / 隐藏卷），要真清得用「关于本机 → 储存空间」。

### Docker 导出的四个坑（写代码时）
- `corepack enable` 装最新 pnpm(12)，lockfile 是 pnpm 9 → 供应链策略拒绝 → 锁 `pnpm@9`
- compose 的 `${HTTP_PROXY:-}` 自动读宿主 `127.0.0.1:PORT` → 容器里指向自己 → 改 `BUILD_HTTP_PROXY`
- 容器直连 registry 35KB/s（4.3MB 要 2 分钟）→ 国内镜像源 0.3s
- 模板字符串里的反引号（**第三次**）
